# Проект mLens — современная Desktop IDE для Kubernetes

Ты — senior software architect, senior TypeScript developer и UI/UX designer, специализирующийся на desktop-приложениях и Kubernetes-инструментах.

Твоя задача — спроектировать и разработать совершенно новое desktop-приложение под названием **mLens**.

Мы используем два проекта в качестве основных референсов:

1. Freelens — https://github.com/freelensapp/freelens
2. Skyhook Radar — https://github.com/skyhook-io/radar

## 1. Главная концепция

mLens — самостоятельная Kubernetes IDE, которая объединяет архитектуру интерфейса Freelens и функциональный UX Skyhook Radar.

Основная идея:

- **Freelens определяет структуру приложения, расположение окон, кнопок, панелей, вкладок и навигацию.**
- **Radar определяет внешний вид и поведение Kubernetes Resource Browser, таблиц, фильтров, карточек ресурсов, деталей ресурсов, иконок, шрифтов и терминала.**

Это принципиальное требование.

Не нужно смешивать два интерфейса случайным образом.

Нужно создать единый продукт, в котором интерфейс организован как Lens, а Kubernetes-инструментарий выглядит и работает как Radar.

### Ключевой принцип

**Application Shell = Freelens**

**Window Management = Freelens**

**Navigation = Freelens**

**Resource Browser = Radar**

**Resource Tables = Radar**

**Resource Details = Radar content inside Freelens window structure**

**Typography, Icons and Design System = Radar**

**Terminal = Radar visual style + Freelens desktop integration**

# 2. Технологический стек

Создать полностью новый репозиторий.

Предпочтительный стек:

- Electron
- React 19
- TypeScript
- Vite / electron-vite
- Node.js
- Zustand
- xterm.js
- node-pty
- Kubernetes JavaScript / TypeScript client libraries

### Критические требования

1. Не использовать Go.
2. Не переносить Go backend из Radar.
3. Не создавать отдельный Go-сервер.
4. Вся бизнес-логика должна быть реализована на JavaScript / TypeScript.
5. Не требовать от пользователя установленного Node.js или Go.
6. Не требовать Docker или отдельного контейнера для запуска приложения.
7. Приложение должно собираться в самостоятельный desktop binary / installer.
8. Пользователь должен просто скачать и запустить mLens.

Допускается использование системных процессов для терминала и Kubernetes-интеграций, если это технически необходимо.

Electron Main Process должен отвечать за привилегированные операции. Renderer должен работать через безопасный типизированный IPC.

# 3. Application Shell — полностью ориентироваться на Freelens

Это фундамент всего приложения.

Изучи Freelens и воспроизведи его общую организацию интерфейса.

Не нужно придумывать новую структуру desktop-приложения.

Нужно сохранить знакомую пользователям Lens организацию рабочего пространства.

## Welcome Screen

Сделать стартовую страницу по аналогии с Freelens.

Она должна включать:

- Список доступных Kubernetes-кластеров.
- Недавно открытые кластеры.
- Избранные кластеры.
- Состояние подключения.
- Добавление нового кластера.
- Импорт kubeconfig.
- Быстрое подключение к кластеру.
- Настройки приложения.

## Cluster Catalog

Реализовать полноценный каталог кластеров:

- Просмотр всех Kubernetes contexts.
- Поддержка нескольких kubeconfig.
- Добавление и удаление кластеров.
- Избранное.
- История подключений.
- Информация о Kubernetes version.
- Информация о текущем namespace.
- Статус подключения.

## Multiple Clusters

Поддержать одновременную работу с несколькими кластерами.

Каждый кластер должен иметь собственную сессию.

При переключении между кластерами пользователь не должен терять состояние открытых ресурсов, вкладок и навигации.

- Панели деталей.

Воспроизвести эту логику в mLens.

Например:

- Расположение кнопок и вкладок — как в Lens.

- Механика открытия ресурсов — как в Lens.

# 5. Resource Browser — полностью Radar

Это один из главных компонентов mLens.

**Resource Browser должен максимально соответствовать Skyhook Radar по внешнему виду, плотности информации и UX.**

Не использовать стандартные таблицы Freelens.

Не делать упрощённую версию Radar.

Изучить исходный код Radar, особенно:

- `web/`
- `packages/k8s-ui/`

Реализовать собственный TypeScript / React интерфейс с использованием подходов и дизайн-системы Radar.

### Требования к Resource Browser

- Таблицы ресурсов в стиле Radar.
- Аналогичная плотность отображения информации.
- Аналогичные размеры строк.
- Аналогичная типографика.
- Аналогичные иконки.
- Аналогичные цвета статусов.
- Поиск.
- Фильтрация.
- Сортировка.
- Фильтрация по namespace.
- Индикаторы состояния.
- Счётчики ресурсов.
- Автоматическое обновление данных.
- Поддержка Custom Resources.
- Поддержка CRD.
- Контекстные действия для ресурсов.

Resource Browser должен быть максимально информативным и компактным, как в Radar.

Избегать больших карточек, пустого пространства и чрезмерно крупных элементов.

# 6. Resource Details — структура окна Lens, содержимое Radar

Когда пользователь нажимает на Kubernetes Resource в таблице, ресурс должен открываться внутри приложения по механике Freelens.

То есть:

- Сохранить структуру окон и вкладок Lens.
- Сохранить расположение кнопок.
- Сохранить навигацию назад.
- Сохранить возможность переключения между открытыми ресурсами.
- Не открывать отдельное браузерное окно для каждого ресурса.

Однако содержимое Resource Details должно быть реализовано в стиле Radar.

### Внутри Resource Details

В зависимости от типа ресурса показывать:

- Overview
- Details
- YAML
- Events
- Logs
- Related Resources
- Metrics
- Conditions
- History

Вкладки и панели должны быть компактными и информативными.

### Пример Pod Details

- Основная информация о Pod.
- Namespace.
- Node.
- IP.
- Status.
- Container status.
- Container images.
- Restart count.
- Conditions.
- Events.
- Logs.
- Previous logs.
- Exec.
- YAML.
- Связанные Deployment, ReplicaSet и Service.

### Пример Deployment Details

- Replicas.
- Available replicas.
- Conditions.
- Rollout status.
- ReplicaSets.
- Pods.
- Events.
- YAML.
- Container configuration.

### Пример Node Details

- Capacity.
- Allocatable resources.
- Conditions.
- Pods.
- System information.
- Events.

Внешний вид деталей должен соответствовать Radar, но управление ими и расположение в приложении — Freelens.

# 14. Критерии качества

Не создавать фиктивные страницы.

Не делать кнопки без функциональности.

Не использовать mock data вместо настоящей Kubernetes integration в готовых функциях.

Не создавать гигантские React-компоненты.

Не смешивать логику Electron и React.

Не использовать Go.

Не делать отдельный Radar внутри mLens.

Не менять Freelens application shell на структуру Radar.

Не менять Radar Resource Browser на стандартные таблицы Freelens.

Если функциональность ещё не реализована, явно обозначать это.
