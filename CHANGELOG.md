# Changelog

Что изменилось в mLens — по людским блокам, а не по файлам. Новые версии сверху.

**Как ведём:** каждое обновление — новая версия `## vX.Y.Z — DD.MM.YYYY, HH:MM`
(patch +1 к предыдущей; время — момент, когда набор изменений собран).
Раздела `Unreleased` больше нет. Более ранняя история (`v2.2.9` → `v2.3.0` и
дальше) — в `git log` и `IMPLEMENTATION_PLAN.md`.

## v2.4.34 — 19.11.2026, 03:27

### Split screen между кластерами
- В строке кластер-табов появилась кнопка **Columns2**: она открывает список
  других открытых кластеров и закрепляет выбранный вторым экраном. Рядом
  появляется чип с именем правого кластера и крестиком «Close split».
- Два полноценных workspace рядом: у каждого свой sidebar, таблица, editor
  area, dock и терминалы. Разделитель тянется (20–80% ширины).
- Активный кластер — левая панель. Клик по табу правого кластера меняет роли
  (он становится левым), закрытие одной панели оставляет вторую и делает её
  активной.
- Все workspace остаются смонтированными (keyed-список, видимость и ширины
  через CSS), так что PTY, скролл и открытые вкладки editor переживают вход и
  выход из сплита. Оба видимых кластера поллят; скрытые, как и раньше, держат
  watch, но не опрашивают API.

## v2.4.31 — 19.11.2026, 02:58

### Editor-area как в VS Code: вкладки ресурсов и split screen
- Ресурсы больше не открываются в одном drawer'е: справа от таблицы появилась
  **editor area** с 1–4 панелями (сетка 2×2). Каждая панель — свой список
  вкладок, свой активный ресурс, своя внутренняя вкладка (Overview/Details/YAML/…)
  и своя история Back на 25 шагов.
- Вкладки ведут себя как в VS Code: перетаскивание для изменения порядка,
  перетаскивание на другую панель для переноса, закрытие средней кнопкой,
  контекстное меню (**Close**, **Close others**, **Close to the right**,
  **Split right / Split down**, перенос в другую панель) и меню `…` со всеми
  вкладками панели.
- Область ресайзится за левый край (360–1200px), разворачивается на всю ширину
  поверх таблицы (Expand) и сворачивается в pill/трей над терминалом — вкладки
  при этом остаются открытыми. Разделители панелей тоже двигаются.
- Фокус панели подсвечивается; Back, Delete, Logs-переходы и Related-навигация
  действуют внутри своей панели. `Esc`/`⌘W` закрывают активную вкладку.
- Состояние переехало из `details`/`detailsHistory`/`resourceTabs` в
  `session.editor`; раскладка живёт в сессии и переживает переключение
  кластеров (после перезапуска приложения сессия, как и раньше, начинается пустой).

## v2.4.29 — 19.11.2026, 00:57

### Производительность: рендерер (A10–A20 из PERF_OPTIMIZATIONS.md)
- **Поиск**: ввод по-прежнему мгновенный, но полный скан инвентаря идёт
  только после паузы в наборе (`useDebouncedValue`, 200мс); haystack всех
  значений колонок + лейблов строится один раз на `items/columns/context` и
  только пока поиск активен. `loadAll` (догрузка страниц) тоже ждёт паузы.
- **Сортировка**: `sortObjects` считает значение колонки **один раз на
  строку** (было — внутри компаратора, O(n log n) вычислений); `sorted`
  сохраняет прежнюю идентичность, если порядок не изменился — обновления
  контекста больше не трогают строки таблицы.
- **Один проход по инвентарю**: `problemCount`, поиск, вкладка Problems и
  колоночные фильтры считаются в одном мемо вместо трёх; опции фильтров
  строятся лениво при открытии popover, `filterableKeys` — из списка колонок
  без скана строк (снят старый кап 2..60 значений — фильтр теперь доступен
  для любых колонок с `filterValue`).
- **Поллинг-хуки держат идентичность** (`lib/stable.ts`): метрики, warnings,
  claimPods, endpoints и nodePodCounts возвращают прежнюю Map, если данные не
  изменились — таймеры перестали инвалидировать `cellContext` и все
  тяжёлые мемо каждые 30–60с.
- **Тонкие Zustand-селекторы** во всём шелле: workspace, сайдбар, браузер,
  дровер, док и табы подписаны на конкретные поля сессии, а не на весь
  объект; вкладки/хотбар/каталог/лаунчер/настройки/AppShell подписаны на
  стабильную сигнатуру `useChromeSessions()` (status + info). Кейсток в поиске
  больше не перерисовывает всю оболочку. Селекторы с `?? []` заменены на
  стабильные константы (паттерн React #185).
- **Ресайз сайдбара** пишет ширину прямо в DOM (`rootRef` на `<aside>`) и
  коммитит в store один раз на `pointerup` — вместо записи на каждый
  pointermove.
- **Строки таблицы** вынесены в memoized `TableRow`: layout
  (`gridTemplate`/`stickyOffsets`) мемоизирован, колбэки — стабильные
  обёртки через `latest`-ref; ререндер родителя больше не пересчитывает
  ячейки видимых строк.
- **Логи**: вместо конкатенации 1.5МБ-строки и `.slice()` каждые 160мс —
  построчный буфер (`lines[]` + хвост без переноса, кап 20000 строк) и
  виртуализация строк через `@tanstack/react-virtual` (с measureElement для
  переносов длинных строк); поиск рендерит отфильтрованный подмножество без
  «дыр». Фриз на болтливых подах (~30k DOM-строк каждые 160мс) убран.
- **Дровер деталей**: поллинг гейтится на `active` + `document.hidden`
  (раньше крутился в скрытых воркспейсах), объект сохраняет идентичность при
  неизменном `resourceVersion` (1740-строчный Overview не перерисовывается
  каждые ≤15с), спиннер/`Refreshing…` — только при первой загрузке и смене
  ресурса; `useRelatedResources` зависит от `uid:resourceVersion`, а не от
  идентичности объекта — вкладка Related не рефетчит связанные списки на
  каждый тик.
- Удалён мёртвый `refreshDetails` из `session-store`.

### Документы
- `AGENTS.md`: правила про тонкие селекторы, стабильность поллинг-хуков,
  precomputed-поиск, memo строк, DOM-ресайз и виртуализацию логов + pitfall
  про TS-сужение на `.constructor ===`.
- `PERF_OPTIMIZATIONS.md`: A10–A20 перенесены в «Сделано».

## v2.4.28 — 18.11.2026, 23:43

### Производительность: сеть (main)
- **Keep-alive соединения**: `kubeRequest` больше не создаёт новый TLS-агент
  на каждый вызов — агенты кэшируются по их опциям (конфиг TLS, прокси,
  клиентские сертификаты exec-плагинов) с `keepAlive: true`. Раньше каждый
  поллинг счётчиков, discovery и каждый рефреш списка платили полный
  TCP+TLS-хэндшейк.
- **Discovery**: запросы по API-группам идут через `mapWithConcurrency(6)`
  вместо 40–60 одновременных (`Promise.allSettled`), общий хелпер вынесен в
  `kubernetes/concurrency.ts`.
- **Helm**: декодирование релиз-секретов кэшируется по `resourceVersion`
  (до 400 записей), а при открытии релиза чужие секреты отсекаются по
  лейблу `name` **до** gunzip — раньше каждый поллинг заново распаковывал
  все ревизии всех релизов.
- **Запись настроек** — debounce 250мс (in-memory состояние остаётся
  синхронным) + синхронный `flush()` на `before-quit`; пути вроде font scale
  больше не пишут файл на каждое событие ввода.

### Производительность: поток watch-событий
- **Батчинг**: main копит события 150мс и отдаёт один IPC-батч
  (`WatchEventBatch`); `ERROR` отправляется сразу. Рендерер применяет батч
  одним проходом (`applyWatchEvents`: индекс по uid/name, последняя операция
  на объект выигрывает) вместо `findIndex` + копии массива на каждое событие.
- **Мульти-namespace watch'и** стартуют с `resourceVersion` списка — раньше
  шли без него, и сервер реплеил **всю коллекцию каждого namespace** как
  ADDED-события поверх только что полученных списков. RV теперь ведётся и из
  списка, и из событий.
- **BOOKMARK больше не доходит до рендера**: RV обновляется в main, а бейдж
  watch переключается синтетическим ping'ом при установке соединения —
  соединение поднялось → «live» сразу, а не по первому изменению ресурса.
- **410 Gone / протухший RV**: вместо вечного повтора одного и того же RV —
  ре-лист `limit=1` для свежего RV и переподключение. Сетевые ошибки теперь
  честно показывают `error` и ретраятся с backoff 5с (раньше — молчаливый
  хаммеринг каждые 500мс).

### Производительность: объёмы данных
- `managedFields` вырезается из list/watch-ответов (`stripServerMetadata`) —
  это крупнейшее поле на объект в больших инвентарях; `get` (детали, YAML,
  дифф) сохраняет его без изменений.

### Документы
- `PERF_OPTIMIZATIONS.md` — полный аудит: сделано (A1–A9), план без потерь
  (A10–A20), варианты с оговорками (B1–B8) и «не стоит делать» (C).

## v2.4.25 — 18.11.2026, 19:48

### Без спиннера при смене namespace
- Клик по Namespace (и любая смена скоупа) теперь обновляет список **тихо**:
  текущие строки остаются на экране, пока не придёт страница нового scope, затем

  больше не появляется.
- Спиннер сохранён там, где он нужен: первый загруз вида, смена вида/кластера,
  ручной Reload (он показывает `Loading…` только в индикаторе свежести).
- Технически `useResourceList` различает смену вида и смену scope: при смене
  только namespace список не очищается, `loading` не включается, данные
  подменяются по завершении запроса; `loadedOnce`/watch-подписки при этом
  продолжают работать.
- Проверено: клик по `dev-network-services` в Pods — picker и строки
  переключились без появления `Loading resources…`.

  правка/применение манифеста.

### Выделение в таблице (selection bar)
- Кнопка **Labels** рядом с Annotate: свои пресеты лейблов
  (`settings.labelPresets`), свой редактор, то же подтверждение и merge-patch.
- Кнопка **Copy names** — окно с копированием имён выделенного: разделитель
  выбирается кнопками (**перенос строк / запятая / точка с запятой**), есть

### Кнопка Create
- **+YAML в browse открывает нижнюю вкладку Create from YAML** — нижнее место
  стало главным. Старый модальный Create-диалог убран (оставался бы мёртвым
  кодом), после Apply из дока все открытые таблицы сами обновляются
  (событие `mlens:resources-applied`).

### Терминал и панели
- **Регулировка высоты дока вернулась**: по верхней кромке — полоса-захват
  8px на всю ширину с видимой ручкой и подсветкой при hover/драге. Высота
  считается от низа дока, поэтому статус-бар больше не даёт сдвиг на 24px;

- Разделители панелей (док, сайдбар, правый drawer) выведены из drag-региона
  окна: раньше `pointerdown` забирало перетаскивание окна, и ресайз молчал.
- Шапка дока: убрана надпись «Terminal»; вместо «＋» и выпадающего меню —
  сгруппированные кнопки **локальный терминал**, **Pod exec** (иконка
  контейнера) и **Create from YAML**. Пустое состояние — карточка с пунктирной
  рамкой и тремя плитками «иконка сверху, подпись снизу».
- Кнопка **New terminal** убрана из верхней панели: терминал открывается из
  дока, по `⌘T` и из командной палитры.
- Свёрнутая полоса открытых ресурсов над доком стала выше (32 → 44px), плашка
  «Show the minimized resource…» поднята на 16px.

### Копирование текста
- Текст в рабочей области (таблицы, детали, YAML, логи, overview, каталог)
  снова выделяется мышью и копируется по `⌘C`. Контентная панель `main`

  полоса кластеров, статус-бар).

- В карточке контейнера появились **Launch parameters** — `command` и `args`
  перед CPU/Memory, свёрнуты по умолчанию, раскрываются как YAML
  (`command:` / `args:` списком) с кнопкой **Copy as YAML**.
- Убраны мёртвые остатки Scale/Pause из Workload Overview — тайпчек снова
  зелёный.

### Хотбар и кластеры
- Правый клик по плитке: **Move up / Move down**, **Connect** (зелёный),
  **Disconnect** (красный), **Remove from hotbar**. Пункт Settings убран,
  как и «Move to slot N».
- Трёхбуквенные инициалы кластера теперь одинаковы в хотбаре, каталоге и
  сайдбаре: имя сначала делится по `-`, иначе работает старая эвристика
  (пробелы → `-`/`_` → `@`, для одного слова — две буквы).
- Каталог красит аватар тем же FNV-1a цветом, что и плитки хотбара (раньше был
  свой градиент). Пин «в избранное» в сайдбаре стал серым вместо янтарного.

### Оформление
- В настройках (раздел **Appearance**, после темы) появился параметр
  **Font size** — множитель, который пропорционально масштабирует все шрифты
  приложения (интерфейс, таблицы, терминал, YAML-редактор), не меняя геометрию:
  отступы, высоту строк таблиц, размеры сайдбара и дока. Свободный числовой
  ввод в диапазоне 50–200%, по умолчанию 100%; значение сохраняется в
  `settings.json` (`fontScale`) и применяется сразу, без перезапуска.

### Установка
- Root-postinstall (`scripts/postinstall.cjs`) теперь **самолечит отсутствие
  Electron-runtime**: если нет `node_modules/electron/path.txt` или `dist/`,
  запускается `node node_modules/electron/install.js` (~100 МБ, кэш в
  `~/Library/Caches/electron`). Свежий клон + `pnpm install` больше не
  заканчивается молчаливым `Error: Electron uninstall`; при
  `ELECTRON_SKIP_BINARY_DOWNLOAD`
  хил пропускается, при падении загрузки postinstall падает с инструкцией
  (лечится вручную: один раз онлайн запустить `node node_modules/electron/install.js`
  или повторить `pnpm install`).
